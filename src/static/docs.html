Добро пожаловать в Webhook Viewer API

Webhook Viewer — это инструмент для тестирования и отладки webhook'ов, созданный командой GREEN-API QA TEAM.

С помощью этого API вы можете создавать временные комнаты для приема webhook'ов, просматривать их содержимое, симулировать ошибки и управлять данными.

🚀 Быстрый старт

  1. Создайте комнату через POST запрос на /room/{id}
  2. Получите URL для приема webhook'ов
  3. Отправляйте webhook'ы на полученный URL
  4. Просматривайте результаты через GET запрос на /hook/{id}

🏠 Управление комнатами

POST /room/{id}

Создает новую комнату для приема webhook'ов.

Параметры:

  • id (path) - Уникальный идентификатор комнаты

Пример запроса:

curl -X POST https://express-webhook-mqmg.onrender.com/room/my-test-room

Пример ответа:

{ "roomId": "my-test-room", "fullUrl": "https://express-webhook-mqmg.onrender.com/hook/my-test-room" }
DELETE /room/{id}

Закрывает комнату и удаляет все связанные данные.

Пример запроса:

curl -X DELETE https://express-webhook-mqmg.onrender.com/room/my-test-room

Пример ответа:

{ "info": "successfully closed room for my-test-room", "roomId": "my-test-room" }
GET /room/all

Получает список всех активных комнат.

Пример запроса:

curl https://express-webhook-mqmg.onrender.com/room/all

Пример ответа:

{ "rooms": ["my-test-room", "another-room"] }
POST /room/{id}/fake-error

Включает или выключает симуляцию ошибок для комнаты.

Тело запроса:

{ "enabled": true, "statusCode": 500 }

Пример запроса:

curl -X POST https://express-webhook-mqmg.onrender.com/room/my-test-room/fake-error \ -H "Content-Type: application/json" \ -d '{"enabled": true, "statusCode": 500}'

Пример ответа:

{ "roomId": "my-test-room", "enabled": true, "statusCode": 500, "message": "Fake error 500 enabled" }
GET /room/{id}/fake-error

Получает текущий статус симуляции ошибок.

Пример запроса:

curl https://express-webhook-mqmg.onrender.com/room/my-test-room/fake-error

Пример ответа:

{ "roomId": "my-test-room", "enabled": true, "statusCode": 500 }

📨 Управление Webhook'ами

GET /hook/{id}

Получает все webhook'и для указанной комнаты.

Пример запроса:

curl https://express-webhook-mqmg.onrender.com/hook/my-test-room

Пример ответа:

[ { "receiptId": "1", "timestamp": "2025-01-15T10:30:00.000Z", "body": { "event": "message.received", "data": { "from": "79991234567", "text": "Hello World" } } } ]
POST /hook/{id}

Отправляет webhook в указанную комнату.

⚠️ Внимание: Если для комнаты включена симуляция ошибок, запрос вернет указанный HTTP код ошибки.

Пример запроса:

curl -X POST https://express-webhook-mqmg.onrender.com/hook/my-test-room \ -H "Content-Type: application/json" \ -d '{ "event": "message.received", "data": { "from": "79991234567", "text": "Hello World" } }'

Пример ответа (успех):

{ "status": "ok" }

Пример ответа (симуляция ошибки):

{ "error": "Simulated 500" }
DELETE /hook/{id}

Удаляет все webhook'и из комнаты.

Пример запроса:

curl -X DELETE https://express-webhook-mqmg.onrender.com/hook/my-test-room

Пример ответа:

{ "status": "cleared" }
GET /hook/{id}/duplicates

Возвращает группы дублирующихся вебхуков в комнате. Сравнение идёт по содержимому body (с канонизацией ключей объектов — порядок ключей не влияет на сравнение, порядок элементов массивов сохраняется). Возвращаются только группы с количеством элементов ≥ 2.

Пример запроса:

curl https://express-webhook-mqmg.onrender.com/hook/my-test-room/duplicates

Пример ответа:

{ "roomId": "my-test-room", "groupsCount": 2, "totalDuplicateWebhooks": 5, "totalWebhooks": 8, "groups": [ { "bodyHash": "a3f1c9e2b740", "count": 3, "body": { "event": "message.received", "data": { "text": "Hello" } }, "receipts": [ { "receiptId": "1", "timestamp": "2025-01-15T10:30:00.000Z" }, { "receiptId": "4", "timestamp": "2025-01-15T10:31:12.000Z" }, { "receiptId": "7", "timestamp": "2025-01-15T10:32:55.000Z" } ] }, { "bodyHash": "b18de40af991", "count": 2, "body": { ... }, "receipts": [ ... ] } ] }

Примечание: body хранится один раз на группу, чтобы ответ оставался компактным даже при тысячах одинаковых хуков. Каждый receipts[i] — это лёгкая ссылка на конкретный экземпляр хука без повторения тела.

DELETE /hook/{room_id}/{webhook_id}

Удаляет конкретный webhook по его ID.

Параметры:

  • room_id (path) - ID комнаты
  • webhook_id (path) - ID webhook'а (receiptId)

Пример запроса:

curl -X DELETE https://express-webhook-mqmg.onrender.com/hook/my-test-room/1

Пример ответа:

{ "status": "deleted", "webhookId": "1", "roomId": "my-test-room" }

⚠️ Коды ошибок

Код Описание
200 Успешный запрос
404 Комната или webhook не найдены
XXX Симулированная ошибка (если включена)

💡 Примеры использования

1. Тестирование Вебхуков

Создайте комнату и используйте полученный URL в настройках webhook'ов для тестирования событий.

2. Отладка интеграций

Проверяйте формат данных, которые отправляет ваше приложение, перед интеграцией с реальным сервисом.

3. Симуляция ошибок

Тестируйте поведение вашего приложения при различных HTTP кодах ошибок (500, 502, 503 и т.д.).

✨ Лучшие практики

✓ Рекомендуется

  • • Используйте осмысленные ID для комнат
  • • Закрывайте комнаты после использования
  • • Очищайте старые webhook'и регулярно
  • • Используйте симуляцию ошибок для тестирования отказоустойчивости

✗ Не рекомендуется

  • • Не используйте для продакшн-данных
  • • Не создавайте слишком много комнат одновременно
  • • Не полагайтесь на долгосрочное хранение данных

🔧 Пример интеграции с GREEN-API

Пошаговый пример настройки webhook'ов для GREEN-API:

Шаг 1: Создайте комнату

curl -X POST https://express-webhook-mqmg.onrender.com/room/myroom # Ответ: { "roomId": "myroom", "fullUrl": "https://express-webhook-mqmg.onrender.com/hook/myroom" }

Шаг 2: Настройте webhook в GREEN-API

Перейдите в настройки вашего инстанса GREEN-API и укажите:

https://express-webhook-mqmg.onrender.com/hook/myroom

Шаг 3: Отправьте тестовое сообщение

Отправьте сообщение через GREEN-API и проверьте webhook:

curl https://express-webhook-mqmg.onrender.com/hook/myroom # Получите все входящие webhook'и

Шаг 4: Протестируйте ошибки

# Включите симуляцию ошибки 502 curl -X POST https://express-webhook-mqmg.onrender.com/room/myroom/fake-error \ -H "Content-Type: application/json" \ -d '{"enabled": true, "statusCode": 502}' # Теперь все webhook'и будут возвращать 502 ошибку # Проверьте как GREEN-API обрабатывает ошибки
